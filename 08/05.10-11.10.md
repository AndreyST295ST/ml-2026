# Отчёт за 05.10–11.10

**Проект:** «Распознавание окружающих звуков»  
**Команда:** 8

## 1. Цель работы за отчётный период

Подготовить выбранную модель классификации звуков к использованию в
веб-приложении: сохранить полностью обученный конвейер, вынести прогнозирование
из экспериментального кода в отдельный модуль, реализовать возврат трёх наиболее
вероятных классов, обработать некорректные входные файлы и проверить модуль
автоматическими тестами.

## 2. Что было сделано

### 2.1. Подготовка и сохранение модели

- Выбранная на предыдущем этапе RBF SVM повторно обучена на fold 1–4 ESC-50,
  всего на 1 600 записях.
- Зафиксированы найденные параметры модели: `C=10`, `gamma="scale"` и RBF-ядро.
- Масштабирование признаков и классификатор объединены в единый конвейер
  scikit-learn, поэтому при прогнозировании используется тот же scaler, что и
  при обучении.
- Добавлена воспроизводимая команда `uv run train-model`.
- Подготовлен версионируемый артефакт `sound_classifier.joblib` размером около
  3,5 МБ. Он содержит обученный конвейер, параметры подготовки аудио, порядок
  424 признаков, список 50 классов и версии схем артефакта и признаков.
- Дополнительно создан читаемый файл `model_metadata.json` с параметрами модели,
  версиями Python и библиотек, метриками и результатами измерения времени.

### 2.2. Отдельный модуль прогнозирования

- Реализован класс `AudioClassifier`, загружающий сохранённую модель без
  повторного обучения.
- Добавлен единый метод `predict`, который принимает путь к аудиофайлу и
  выполняет загрузку, преобразование в mono, resampling, приведение к пяти
  секундам, нормализацию, извлечение улучшенных признаков и классификацию.
- Метод возвращает три класса с наибольшей уверенностью и полное время обработки
  записи.
- Уверенности получаются нормализацией one-vs-rest оценок SVM с помощью softmax.
  Они сохраняют порядок классов модели и в сумме по всем 50 классам равны
  единице, но не интерпретируются как независимо откалиброванные вероятности.
- Добавлена команда `uv run predict-sound path/to/recording.wav`, выводящая
  результат в JSON. Поддерживаются контейнеры WAV, FLAC и OGG.

### 2.3. Обработка ошибок

- Добавлены понятные ошибки для отсутствующего файла, неподдерживаемого
  расширения и повреждённого аудиоконтейнера.
- При загрузке модели проверяются версия артефакта, версия схемы признаков,
  параметры аудио, точный порядок признаков и соответствие списка классов
  обученному классификатору.
- Добавлена проверка параметра `top_k`, чтобы нельзя было запросить нулевое или
  недоступное количество классов.
- Эти проверки не позволяют продолжить прогнозирование с несовместимой моделью
  или частично прочитанными данными.

### 2.4. Тестирование и проверка качества кода

- Добавлены тесты загрузки модельного артефакта и получения ранжированных
  уверенностей для реального аудиофайла.
- Добавлены тесты обработки неподдерживаемого расширения, повреждённого WAV и
  несовместимой структуры артефакта.
- Добавлен интеграционный тест, проверяющий, что сохранённая модель проекта
  загружается и содержит 50 классов и 424 признака.
- Общее количество автоматических тестов увеличилось с 7 до 12; все 12 тестов
  успешно проходят.
- Статический анализ и проверка форматирования Ruff проходят без замечаний.

## 3. Полученные результаты

### 3.1. Проверка сохранённой модели на fold 5

| Показатель | Значение |
|---|---:|
| Accuracy | 0,6250 |
| Macro F1 | 0,6037 |
| Правильно классифицировано записей | 250 из 400 |
| Размер модельного артефакта | около 3,5 МБ |

Метрики сохранённого конвейера совпали с результатами выбранной на предыдущем
этапе модели. Fold 5 по-прежнему не используется ни для обучения, ни для выбора
параметров.

### 3.2. Полное время прогнозирования

Время измерено на 50 записях fold 5 после одного прогревочного вызова. В замер
входят чтение аудио, подготовка сигнала, извлечение 424 признаков и вычисление
уверенностей. Загрузка модели не входит в это время, так как сервер будет
загружать её один раз при запуске.

| Показатель | Время, мс/запись |
|---|---:|
| Среднее | 18,57 |
| Медиана | 18,64 |
| 95-й процентиль | 18,96 |
| Минимум | 17,46 |
| Максимум | 19,56 |

Первый вызов в новом процессе может занимать больше времени из-за однократной
инициализации библиотек обработки аудио.

### 3.3. Ручная проверка команды прогнозирования

Команда проверена на записи дождя `1-17367-A-10.wav`. Модель вернула следующие
три класса:

| Место | Класс | Уверенность |
|---:|---|---:|
| 1 | `rain` | 0,8350 |
| 2 | `helicopter` | 0,1126 |
| 3 | `door_wood_creaks` | 0,0152 |

Правильный класс оказался на первом месте. Этот запуск использовался как
функциональная проверка сохранения, загрузки и полного конвейера, а не как
дополнительная оценка качества модели.
